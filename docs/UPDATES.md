# Обновления NCreate Launcher и официальных сборок

## Состояние и границы

Публичная v0.5.0 Beta была собрана до появления Tauri updater и не умеет обновлять себя. Первый переход с установленной v0.5.0 на следующий подписанный выпуск требует обычной установки нового файла из GitHub Releases. После этого установленный лаунчер сможет проверять и устанавливать последующие подписанные обновления. Новый релиз ради проверки Stage 3 не опубликован.

Карточки Minimal, Standard и Ultra остаются «Скоро» до публикации настоящих production manifests. Тестовые manifests не предлагаются игрокам.

## Обновление приложения

Нативный модуль `apps/app/src/launcher_updates.rs` использует официальный Tauri v2 updater. Интерфейс обращается к нему только через локальный IPC `launcher_check_update` и `launcher_install_update`; токены и ключ подписи в WebView не попадают. При запуске выполняется проверка, если включена настройка автоматической проверки. Ручная проверка доступна всегда.

Список релизов читается как JSON из `https://api.github.com/repos/Yozekkk/ncreate-launcher/releases`. Для Stable отбираются только стабильные опубликованные релизы; Beta допускает также prerelease. Релиз без `latest.json` не рассматривается как обновление. Это исключает неподписанную v0.5.0, даже если GitHub считает её обычным release. Из выбранного релиза загружается его `latest.json`; Tauri получает адрес metadata, сравнивает SemVer, загружает пакет, проверяет подпись и устанавливает его. Перед установкой также сверяются заявленный размер и SHA-256 пакета. Проверка канала, версии, платформы и GitHub URL выполняется до установки, а `requireSignedVersion` связывает объявленную версию с подписанным файлом.

Подписанные artifacts следующего релиза: Windows NSIS `.exe` и `.exe.sig`, Linux `.AppImage` и `.AppImage.sig`. DEB публикуется для ручной установки, Tauri updater Linux использует AppImage. Metadata содержит `version`, `channel`, `notes`, `pub_date` и `platforms` с URL, inline-подписью, размером и SHA-256. Публичный ключ находится в `apps/app/tauri.conf.json` (`plugins.updater.pubkey`). Приватный ключ никогда не входит в Git.

Оба ключевых файла основной локальной копии владельца находятся вне репозитория в `~/.local/share/ncreate-release-signing/`, резервная копия — в `~/.local/state/ncreate-release-signing-backup/`; каталоги имеют права 0700, файлы 0600. В GitHub Actions заданы secrets `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Их значения не нужны для чтения или редактирования исходников. При потере всех приватных копий выпустить обновление для уже установленных клиентов с этим публичным ключом будет невозможно.

## Публикация новой версии приложения

Обновите версии в package/Cargo/Tauri metadata и создайте `docs/releases/vX.Y.Z.md`. Первая строка release notes определяет название выпуска и канал: Beta в заголовке или prerelease SemVer помечает канал Beta. После успешного CI создайте и отправьте тег `vX.Y.Z` на проверенный commit. `.github/workflows/release.yml` автоматически собирает Linux и Windows, подписывает AppImage/NSIS, создаёт `latest.json`, `SHA256SUMS.txt`, исходный архив и GitHub Release. Публикация происходит только после проверки всех обязательных assets и контрольных сумм; ошибочный набор остаётся черновиком. `.github/workflows/check.yml` применяет `apps/app/tauri.ci.conf.json` и проверяет обычные pushes/PR без доступа к signing secrets.

Отдельная коммерческая Authenticode-подпись Windows installer не настроена: подпись Tauri updater доказывает происхождение файла самому лаунчеру, но не заменяет сертификат для SmartScreen.

## Обновление официальных сборок

`packages/launcher-core/src/editions.rs` использует существующий Stage 2 manifest/update engine. Публичные каналы ищут JSON по адресам `https://raw.githubusercontent.com/Yozekkk/ncreate-manifests/main/channels/{stable|beta}/{minimal|standard|ultra}.json`. Отсутствующий manifest (HTTP 404) означает «Скоро», а не фиктивную сборку. Схема v1 и процесс публикации находятся в [репозитории манифестов](https://github.com/Yozekkk/ncreate-manifests). Данные пользователя хранятся отдельно в `~/.local/share/ncreate-launcher` на Linux или в каталоге данных приложения на Windows.

Каждый manifest определяет edition, версию, Minecraft и loader, канал, changelog, Java/RAM bounds и файлы. Для файла задаются относительный путь, HTTPS URL, SHA-256, размер, обязательность и политика `managed_only` либо `preserve`. Прямые исполняемые файлы и скрипты, обход каталогов, пути к saves/logs/screenshots/options, приватные сетевые адреса и превышение лимитов отклоняются. Managed files сравниваются по hash: добавленные и изменённые скачиваются, неизменённые остаются, удаляются только ранее принадлежавшие manifest файлы. Пользовательские worlds и моды не удаляются; конфликт пользовательской правки с новым managed file останавливает обновление с ошибкой.

Перед применением движок сохраняет journal и предыдущие файлы. Загрузка идёт во временную область, затем проверяются размеры/хеши и выполняется транзакционное применение. При ошибке или прерывании журнал восстанавливает прежнее состояние. Если сохранена предыдущая версия, Библиотека предлагает «Восстановить предыдущую версию»; откат также отказывается перезаписывать файлы, изменённые пользователем после обновления.

## Проверка

Детерминированные тесты покрывают отбор Stable/Beta, неверный metadata URL/канал/размер, криптографическую подпись и её повреждение, diff v1→v2, hash mismatch, отмену, сохранение worlds/user mods, rollback и восстановление после прерывания. Подписанный Linux AppImage и `.sig` проверяются локальной production сборкой; GitHub workflow публикует их только на новом теге. Успешная установка нового launcher через updater и Windows GUI требуют двух реально опубликованных подписанных версий и Windows runtime-теста соответственно. Не отмечайте эти сценарии как PASS до фактической проверки.
